# 地图管理：最小闭环

云平台改当前图，经 MQTT 下发给 Gateway，Gateway 调 nav 的导入接口，nav 写入底盘。底盘网页上能看到站点或路径变了，这条就通了。

nav 不接 MQTT。MQTT 是云平台和 Gateway 的事，和现在任务下发一样。

## 和机器狗 PDF 的差别

`机器狗功能集成-第二阶段.pdf` 第 3.2 节是：前端点按钮，后端发 MQTT，设备执行，`services_reply` 回执。主题是 `thing/product/dog/{sn}/services`。

那里的 `map_sync` 是设备把本地图归档上传到 MinIO，不是把云端改好的图写回本体。我们这期不做上传、不做删图、不做切图、不做建图。只做写回当前图。

机器狗页面只有建图和站点角度。珞石还有路网。云平台要能改路径并放进下发数据，否则 nav 没有路可导入。只改了站点、数据里没有路径时，导入保留底盘原有路网。

## 端侧这一刀

nav 增加一个口，只处理当前图：

```text
POST /maps/import
```

Gateway 把云平台这份当前图交进来。nav 换成底盘单位，调用珞石 `POST /api/v0/map/import` 导入。导入后从底盘再读一次，和交进来的站点、路径一致才算成功。

正在 `/goto` 时拒绝导入。天机适配器先返回「还没有」。

自己先验证，不必等 MQTT：用一份改过站点名或坐标的当前图调用这个口，打开底盘网页 `http://192.168.71.50`，看到该站点变了即可。

## 请其他组配合

| 谁 | 做什么 |
|---|---|
| 云平台前端 | 编辑当前图。站点沿用现有页。珞石要另加路径：起终点、结点、C/D、车头朝向、速度、代价。保存的是当前图整份数据 |
| 云平台后端 | 保存后按现有 MQTT 下发到这台车的 Gateway。带上当前图的站点和路径。等 `services_reply` |
| Gateway | 收到下发后 `POST` nav `/maps/import`，把 nav 的结果原样回执。不要自己改底盘 |
| nav | 只做上面的导入口，写入珞石底盘 |

下发报文建议沿用 PDF 的 `method` / `bid` / `tid` / `data`，方法名不要用 `map_sync`（那个是上云）。可用 `map_apply`，`data` 里是当前图的站点和路径。具体字段等导入口的请求体定稿后给一版。
